# 도구 조회 범위 안내 보완 확인

## 문제와 수정

이전 [실제 Ollama 답변 검토](ollama_review.md)에서 `get_monitoring_status로 CPU 사용률과 최근 배포/트래픽 변화 시점 확인 필요`라는 안내를 발견했다. CPU runbook의 첫 문장을 따른 답변이지만, 현재 도구는 배포·트래픽 변화 이력을 반환하지 않는다.

`agent/grounding.py`의 공통 작성 지시와 근거 입력에 다음 내용을 추가했다. Ollama와 OpenAI가 함께 사용한다.

- 도구가 반환하는 시스템명·현재 상태·CPU·메모리·조회 시각·알림 문구를 명시한다.
- 배포 이력·트래픽 변화 이력·시계열 지표·로그 원문·프로파일링 결과는 조회 범위 밖이라고 설명한다.
- 매뉴얼의 지시가 도구의 기능을 넘더라도 조회 가능하다고 안내하지 않도록 한다.
- 필요한 정보는 미수집으로 표시하고 배포 기록·시계열 지표·로그 등 별도 자료를 요청하도록 한다. 알림 안의 수치는 알림 내용으로 인용할 수 있다.

별도의 데이터 수집 기능을 추가한 것은 아니다. 기존 runbook은 유지했으며, 잘못된 도구 사용 지시가 포함된 동일 매뉴얼을 전달한 상태에서도 수정된 작성 지시를 따르는지 확인했다.

## 확인 결과

- 외부 모델 호출 없는 자동 테스트 23개 통과. 기존 회귀 테스트와 두 백엔드에 조회 범위 지시가 전달되는 것을 확인했다.
- 실제 로컬 `qwen3:0.6b`/`qwen3:8b`와 전체 LangGraph를 등록 대상 질문으로 1회 실행했다. 모니터링 MCP 응답은 이전 실험과 같은 고정 데이터이며, 원래 CPU runbook을 사용했다.
- 모니터링 대상은 payments-service였고 답변 검증은 1회에 통과했다. LangSmith 추적은 끄고 `.env`·웹 서버·SQLite는 사용하지 않았다.
- 답변·프롬프트·토큰·관련 소스 SHA-256은 [후속 실행 JSON](tool_scope_check.json)에 저장했다.

수정 후 답변의 해당 부분:

```text
2) 추가 확인 사항
- 배포 이력, 트래픽 변화 이력, 시계열 지표, 로그 원문, 프로파일링 결과는 조회 범위 외로 미수집 상태
- CPU 사용률 지속 시간 또는 변화 추이 판단 불가 (단일 시점 수치 기준)

3) 조건부 권고
- 배포 시점 확인 필요 시: 별도 배포 기록 요청 (배포 이력 조회 불가)
- 로그 분석 필요 시: 로그 미수집으로 인해 원인 확인 불가, 별도 로그 자료 요청 필요
```

이번 실행은 43.70초, 누적 2,732토큰이었다. 별도 워밍업 없이 수행한 수정 후 1회 확인이며, 이전 실험과 실행 조건이 같지 않아 속도·토큰 개선률로 비교하지 않는다. [기존 6회 비교](ollama_comparison.md)는 이번 수정 전 코드의 측정 기록으로 유지한다.

같은 질문을 고정 데이터로 다시 실행하려면 프로젝트 루트에서 다음 명령을 사용한다. 응답 JSON을 표준 출력으로 반환하며 기존 결과 파일은 덮어쓰지 않는다.

```bash
LANGCHAIN_TRACING_V2=false LANGSMITH_TRACING=false \
.venv/bin/python3 eval/compare_ollama.py \
  --worker-source "$PWD" --case-id cpu_incident --label tool_scope_followup
```

## 남은 한계

- 실제 모델 답변 1건에서 기대한 안내를 관찰했다. 도구 능력에 대한 자연어 주장을 코드로 검증하는 기능을 추가한 것은 아니며 항상 지시를 따른다고 보장하지 않는다.
- 조회 범위 설명은 현재 도구 구현에 맞춘 정적 설명이다. 도구의 반환 범위가 바뀌면 함께 갱신해야 한다.
- OpenAI는 작성 지시 전달을 테스트용 응답으로만 확인했다. 실제 OpenAI API 호출과 수정 후 브라우저 화면 확인은 이번 검증에 포함하지 않았다.
