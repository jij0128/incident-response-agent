## 미등록 시스템 확인 개선 (v2)

- 그래프 시작 시 `target_check`에서 `data/monitoring.json`의 시스템 목록과 대조한다.
- 미등록 식별자가 있으면 대상 확인 답변으로 종료한다. `/chat`과 `/chat/stream`에 모두 적용된다.
- 검사 범위는 `-service`/`_service`가 포함된 식별자와 `web-02` 같은 숫자 접미사 호스트명이다.
- 등록된 이름은 대소문자를 포함해 정확히 일치해야 한다. 자연어 별칭과 이름이 생략된 요청, legacy v1의 처리는 이번 변경 범위에 포함하지 않는다.
- 실행: 프로젝트 폴더에서 `LANGCHAIN_TRACING_V2=false .venv/bin/python3 -m unittest discover -s tests -v`

## 답변 근거 구분과 퍼센트 인용 검증 (두 번째 개선)

- Ollama와 OpenAI의 작성 지시를 `agent/grounding.py`에서 공유한다. 관측 결과, 매뉴얼의 미실행 절차, 모델의 추정 의견을 구분해서 전달한다.
- 모니터링 필드/알림과 매뉴얼에 없는 퍼센트 수치를 쓰면 재작성 사유를 반환한다. 사용자 요청과 모델의 분석 문장은 수치의 근거로 인정하지 않는다.
- 최대 3회 실패하면 검증 실패로 기록하고, 모델이 쓴 초안 대신 코드로 구성한 실제 수집 상태를 최종 답변으로 반환한다.
- 단위 검사 사례: 실제 CPU 95.9%, 메모리 57.4%에서 CPU를 99.9%/100%/53.5%로 바꾼 고정 합성 오답 3건을 동일하게 비교했다. 기존 형식 검사는 3/3건 통과, 변경 후는 0/3건 통과. 정확한 인용 1건은 양쪽 모두 통과한다. 이 결과는 실제 모델 정확도나 지연시간의 실측 결과가 아니다.
- 실제 화면 확인: 백엔드 재시작 후 `payments-service 결제 응답이 느려지고 CPU가 치솟았어요, 원인 확인해주세요.`를 입력한다. 현재 수치와 알림의 수치를 구분하는지, 로그/지속시간은 미확인으로 표현하는지, 매뉴얼의 조건을 유지하는지 사람이 확인한다.
- 실제 Ollama UI 확인 결과 (2026-10-20, 사용자 공유 화면 1건): 현재 CPU 94.2%/메모리 56.6%와 알림의 CPU 91%를 구분했다. 로그 미수집, 단일 시점으로 지속시간 추정 불가, 배포 이력 미확인을 표시하고 확장/롤백을 조건부 권고로 작성했다. 개선 전의 "로그 패턴 없음" 단정을 이 사례에서는 반복하지 않았다. 한 건의 정성 확인이며, 고정 합성 검증 사례의 결과와 별도로 기록한다.
- 한계: 퍼센트의 존재 여부 검사로, 동일한 수치의 잘못된 서비스/지표 귀속과 다른 단위의 수치·자연어 주장까지 검증하지 않는다. 로그·지속시간에 대한 작성 지시는 모델이 따르는지 별도 관찰이 필요하다. 스트리밍 초안은 최종 검증 전에 화면에 노출될 수 있다.

## 도구 조회 범위 안내 보완

- 질문: `payments-service 결제 응답이 느려지고 CPU가 치솟았어요, 원인 확인해주세요.`
- 확인 기준: 현재 도구가 배포 이력·트래픽 변화 이력·시계열·로그를 조회한다고 안내하지 않아야 한다. 미수집임을 표시하고 별도 배포 기록·시계열 지표·로그 자료가 필요하다고 안내해야 한다.
- 공통 작성 지시에 현재 도구의 조회 범위를 명시했다. CPU 매뉴얼의 기존 조회 지시가 포함돼도 기능 범위가 우선하도록 한다.
- 자동 테스트 23개 통과. 수정 후 실제 Ollama와 고정 MCP 응답을 사용하는 그래프 실행 1건에서 이력 미수집 표시와 별도 배포 기록 요청을 확인했다. [실행 기록](../eval/results/tool_scope_check.md) 참고.
- 수정 후 브라우저 화면 재확인은 아직 하지 않았다. 백엔드를 재시작한 후 위 질문으로 동일한 안내가 나오는지 확인한다.
