# 2일차 완료 상태와 3일차 준비

2026-10-20에 사용자가 요청한 2일차 범위까지 선행 완료했다. 여기서 2일차 완료는 **구현·검증·보고서와 발표 초안 준비**를 뜻한다. 10월 21일이 지났다는 뜻이나 최종 제출을 했다는 뜻은 아니다.

## 완료

- 미등록 대상 확인, 근거 구분·도구 범위 안내, 퍼센트 검사·실패 처리
- 스트리밍 빈 업데이트 처리, 관리자 조회 및 채팅 UI 개선
- 고정 규칙 비교와 실제 Ollama 전후 비교, 후속 도구 범위 검증
- 실제 Chrome의 등록·미등록·혼합 질문 및 새 화면 확인
- 실제 LangSmith에 승인된 모의 요청 2건 저장·조회
- 실제 OpenAI·MCP·FastAPI SSE의 등록·미등록·혼합 질문 확인
- Python 23개 + 프론트 이벤트 8개 재검사 통과
- [결과 보고서](PROJECT_REPORT.md), [Apple Pages 발표자료·대본](presentation/) 작성. 기존 PPTX도 발표 폴더에 보관했다.

OpenAI 최종 확인은 등록 질문 API 4회·1,697토큰·검증 1회 합격이며 미등록·혼합 질문은 API 호출 0회로 이름 확인을 요청했다. [원시 기록과 해석](../eval/results/openai_check.md)에 조건과 한계를 남겼다. 일반 추적 설정, 기존 대화 DB, 실행 중 앱 설정은 변경하지 않았다.

1. **발표 연습과 코드 설명**: 실제 배정 시간에 맞춰 대본을 조정하고, Pages 발표자료를 발표할 기기에서 열어 한글 글꼴과 줄바꿈·페이지 표시 방식을 확인한다.
2. **시연 리허설**: 등록 질문의 사실/미수집/조건부 권고, 미등록·혼합 질문의 확인 안내를 보여준다. CPU는 모의 변동값이므로 캡처와 같은 값일 필요가 없다. 근거 없는 원인 단정 여부를 직접 읽고 판단한다.

## 시연 순서

```text
1. payments-service 결제 응답이 느려지고 CPU가 치솟았어요, 원인 확인해주세요.
2. billing-service 응답이 느려요. 원인 확인해주세요.
3. payments-service와 billing-service 둘 다 응답이 느려요. 원인 확인해주세요.
```

추적이 꺼진 관리자 화면은 새 요청이 기록되지 않는 것이 정상이다. 기존 모의 연동 결과는 보고서로 설명한다. 시연을 위해 추적을 켜면 질문·답변·프롬프트·실행 정보가 LangSmith로 전송되므로 별도 전송 범위를 확인해야 한다. OpenAI 재시연은 실제 비용이 발생한다. 기존 캡처와 JSON 결과로 설명할 수도 있다.

실행 스크립트는 이전 포트 프로세스를 종료하고 DB를 초기화하므로 발표 직전에 무심코 재실행하지 않는다. 실행과 테스트 방법은 [README](../README.md)에 있다.
